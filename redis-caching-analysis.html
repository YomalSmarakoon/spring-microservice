Dimension 01

Cache Access Pattern

How the service reads from and writes to Redis. The book implements cache-or-fetch imperatively at every call site. The modern approach declares intent once via an annotation and lets the framework manage the mechanics.

Book — Manual RedisTemplate
// OrganizationRedisRepository HashOperations<String,String,Organization> hash; public Organization findOrganization(String id) { return hash.get(HASH_NAME, id); } public void saveOrganization(Organization org) { hash.put(HASH_NAME, org.getId(), org); } // LicenseService — cache logic here too org = redisRepo.findOrganization(id); if (org == null) { org = feignClient.getOrganization(id); if (org != null) redisRepo.saveOrganization(org); }
Cache logic is duplicated across the repository and service layers. A second client path (REST, Discovery) must repeat the read-through pattern manually — and will drift.
Modern — @Cacheable declarative
// OrganizationCacheClient — one declaration @Cacheable( cacheNames = "organizations", key = "#organizationId", unless = "#result == null" ) public OrganizationResponse getOrganization( String organizationId) { LOG.info("Cache miss — calling service"); return feignClient.getOrganization(organizationId); } // LicenseService — no Redis knowledge needed org = orgCacheClient.getOrganization(id);
Cache-or-fetch logic exists in exactly one place. LicenseService has no awareness of Redis — it calls getOrganization and gets a result, cached or not.

Dimension 02

The Double-Proxy Problem

Feign wraps OrganizationFeignClient in a JDK dynamic proxy. Spring AOP caching wraps beans in a second proxy. Stacking both on the same object — putting @Cacheable on the Feign interface — breaks silently depending on CGLIB mode and AOT settings. The book avoids the conflict by not using Spring AOP caching at all; the modern code solves it properly.

Book — Conflict avoided (by accident)
// Book never applies @Cacheable // to a Feign interface — it uses // a concrete repo with RedisTemplate. // The proxy conflict never arises // because Spring AOP is not involved. @Repository public class OrganizationRedisRepository { // manual HashOperations — no AOP proxy }
The conflict is avoided by not using the cache abstraction at all. The cost is every Redis operation being handwritten, with no TTL, no error handling, and no framework-managed serialization.
Modern — Separation by design
// Feign interface — pure HTTP transport. // No @Cacheable here. One proxy layer. @FeignClient(name = "organization-service") public interface OrganizationFeignClient { ... } // Concrete @Service — safe for AOP proxy. // Spring wraps this class cleanly. @Service public class OrganizationCacheClient { // @Cacheable lives here. // Transport and caching never share // a proxy chain. }
Each layer does exactly one job. The Feign proxy handles HTTP transport; the Spring AOP proxy handles cache interception. They never meet on the same object.

Dimension 03

Cache Configuration

TTL, serialization format, and null-value handling. The book relies on defaults and manual property files. The modern CacheConfig makes all three explicit in code.

Book — Implicit defaults
# application.properties redis.server=localhost redis.port=6379 // No RedisCacheManager configured. // Serializer: JdkSerializationRedisSerializer // → binary blobs in redis-cli, unreadable. // TTL: none — entries live until deleted. // A missed eviction = stale data forever. // Null guard: none. // org-not-found → null cached → served // to all callers until service restarts.
Works out of the box, but entries never expire, cache contents are opaque in redis-cli, and a null response from the org service poisons all future lookups with no TTL backstop.
Modern — CacheConfig
@Bean RedisCacheConfiguration defaultCacheConfiguration() { return RedisCacheConfiguration.defaultCacheConfig() .entryTtl(Duration.ofMinutes(30)) .serializeValuesWith( /* GenericJackson2JsonRedisSerializer */ ) .disableCachingNullValues(); } // TTL: 30-min backstop for missed events. // Serializer: JSON — readable in redis-cli. // Nulls blocked at config layer AND // at annotation (unless="#result==null").
TTL is a backstop when Kafka events don't arrive. JSON makes entries inspectable during debugging. Null values are blocked at two independent layers — neither can be bypassed by accident.

Dimension 04

Redis Failure Behavior

A cache is a performance optimization. Its absence should degrade performance, not stop the service. The book does not configure a Redis error handler, which means a Redis outage propagates as a 500 to every license lookup — even though PostgreSQL and the org service are both healthy.

Book — Uncaught exception
// No error handler configured. // RedisConnectionFailureException // propagates up the call stack. GET /licenses/123 → LicenseService.getLicense() → redisRepo.findOrganization() → RedisConnectionFailureException → HTTP 500 ✗ // Postgres healthy. Org service healthy. // Service appears down because a cache // became a hard dependency.
A Redis outage takes down the entire license lookup. The cache — a performance layer — is now a reliability dependency. Every request fails until Redis recovers.
Modern — CacheErrorHandler via CachingConfigurer
public class CacheConfig implements CachingConfigurer { @Override public CacheErrorHandler errorHandler() { return new CacheErrorHandler() { handleCacheGetError() { LOG.warn(...); } handleCachePutError() { LOG.warn(...); } handleCacheEvictError() { LOG.warn(...); } }; } } // Redis down → logged warning → fall through // to org-service HTTP call. Request succeeds // at cost of one extra network hop.
Redis failure becomes a monitored warning, not a thrown exception. The request continues — slower, but successful. The cache degrades gracefully back to direct service calls.

Dimension 05

Cache Invalidation

How a Kafka event evicts a stale organization entry. The book calls hashOperations.delete() directly from the handler. The modern code delegates to a separate bean — avoiding the self-invocation trap where calling an @CacheEvict method from within the same class bypasses the AOP proxy and silently does nothing.

Book — Direct hash delete
@StreamListener(Sink.INPUT) public void logOrganizationChange( OrganizationChangeModel change) { if ("UPDATE".equals(change.getAction()) || "DELETE".equals(change.getAction())) { orgRedisRepo.deleteOrganization( change.getOrganizationId()); } } // CREATE events skip eviction — // correct, but implicit. // New action types need manual guard updates.
The action-type guard is a subtle maintenance risk: any new action type added in future must be explicitly handled here, or eviction silently skips it. The intent is obscured inside a conditional.
Modern — @CacheEvict on dedicated bean
// OrganizationCacheInvalidator — own bean. // AOP proxy fires on every external call. // Self-invocation trap cannot occur. @CacheEvict( cacheNames = "organizations", key = "#event.organizationId" ) public void invalidate( OrganizationChangeModel event) { LOG.info("Evicted. action={}, id={}", ...); } // No action-type guard needed. // Evicting a missing Redis key = safe no-op. // CREATE, UPDATE, DELETE handled identically.
All event types call invalidate() without branching. Evicting a non-existent Redis key costs a round-trip and nothing else. No conditional to maintain as the event schema evolves.

Dimension 06

Messaging Consumer API

How the Kafka listener is declared. @StreamListener and @EnableBinding were deprecated in Spring Cloud Stream 3.1 and removed in 4.x. Any project upgrading its BOM past the book's version finds the consumer does not compile.

Book — @StreamListener deprecated
@EnableBinding(Sink.class) @SpringBootApplication public class LicensingServiceApplication { ... } // Handler class @StreamListener(Sink.INPUT) public void logOrganizationChange( OrganizationChangeModel change) { // handle event } // @EnableBinding, @Input, @Output, // Sink, Source — all removed in 4.x.
Compiles against the book's pinned versions. Breaks the moment the Spring Cloud BOM is updated past the deprecation window — a common first step when upgrading to Spring Boot 3.
Modern — Consumer<T> functional current
// Bean name → binding name convention: // "organizationChangeConsumer" // → "organizationChangeConsumer-in-0" // Configured in application.yml. @Bean public Consumer<OrganizationChangeModel> organizationChangeConsumer() { return event -> { cacheInvalidator.invalidate(event); }; } // No framework annotations on the handler. // Testable without loading any Kafka infra.
A plain Java functional interface registered as a Spring bean. No framework-specific annotations on the consumer itself — it can be tested in isolation with a mock event, no broker required.
Side note

OrganizationResponse — constructor visibility

Your diff quietly makes the no-arg constructor public (was package-private). This is not optional: GenericJackson2JsonRedisSerializer calls Jackson to deserialize the JSON stored in Redis back into an object. Jackson requires either a public no-arg constructor or a @JsonCreator-annotated one. A package-private constructor produces a JsonMappingException at runtime — the cache write succeeds, but the next read crashes. The book's binary JDK serializer bypassed this entirely; switching to JSON surfaces it.
